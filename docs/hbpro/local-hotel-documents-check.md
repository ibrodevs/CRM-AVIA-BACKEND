# Проверка сертификата проживания, номеров и фотографий

## Что изменилось

В заказе раскройте гостиничную услугу. Для HBPRO появились:

- «Скачать сертификат на проживание (PDF)»;
- «Номера и фотографии гостиницы»;
- внутри каталога — «Скачать перечень номеров (CSV)» и ссылки открытия оригиналов фотографий.

Сертификат создаётся в CRM по последним сохранённым данным подтверждённого
бронирования. Он содержит отель, адрес, даты, гостей, категории номеров и номера
подтверждения. Себестоимость и наценка в PDF не выводятся. Документ сохраняется
в разделе «Документы» того же заказа как ваучер, привязанный к услуге.
Повторное скачивание неизменённого сертификата не создаёт дубль.

Это **документ CRM, не оригинальный ваучер HBPRO**. Отдельного метода выдачи
ваучера в опубликованном API HBPRO не найдено. Оригинал, полученный от поставщика,
можно прикрепить существующей кнопкой «Добавить файл».

Для отменённой брони доступен отдельный PDF с отметкой «ОТМЕНЕНО - НЕ ДЕЙСТВУЕТ
ДЛЯ ЗАСЕЛЕНИЯ». Пока подтверждения нет или отмена ещё выполняется, выдача
сертификата недоступна. Если статус изменился после формирования документа,
скачивание устаревшей версии блокируется: сформируйте новый через услугу.

Каталог запрашивает Hotel Details и Hotel Rooms HBPRO, использует существующий
общий supplier cache с TTL сутки. Каталог отделён от тарифов: наличие и цена
на конкретные даты определяются поиском. Если HBPRO не передал фотографии или
категории, интерфейс показывает это явно. CSV содержит категории, описание,
удобства и ссылки на оригиналы фото; выгрузка защищена от CSV formula injection.
Для сохранения самой фотографии нажмите «Открыть / сохранить фото» и сохраните
открывшийся оригинал средствами браузера.

API: https://api.hbpro.expert/docs/ (OpenAPI: https://api.hbpro.expert/docs/swagger.json).

## Быстрая проверка без HBPRO, без настоящего бронирования

В обычной локальной БД на момент разработки нет HBPRO-бронирований. Поэтому
добавлен отдельный localhost demo. Он создаёт **свою БД**, три тестовых заказа и
локальные изображения. Все обращения адаптера HBPRO перехватываются внутри
процесса; финансовые запросы заблокированы. В PDF есть отметка демонстрации;
картинка — тестовое изображение, а не фотография реального отеля.

Demo уже был запущен разработчиком на `http://127.0.0.1:3000` и `:8000`.
Если процессы остановлены, запустите их по инструкции ниже. Не запускайте jobs
или scheduler с demo-БД и не используйте её как обычный backend.

### Терминал 1: backend

```bash
cd /Users/Apple/Desktop/projects/crm/CRM-AVIA-BACKEND
.venv/bin/python -m pip install -e .

# Только при первом запуске: создать отдельную локальную БД.
# Если already exists — перейти к migrate, не удалять существующую БД.
createdb travelhub_hbpro_ui_demo

DATABASE_URL=postgres:///travelhub_hbpro_ui_demo \
DJANGO_SETTINGS_MODULE=config.settings.dev HBPRO_ENVIRONMENT=sandbox \
.venv/bin/python manage.py migrate --noinput

DATABASE_URL=postgres:///travelhub_hbpro_ui_demo \
DJANGO_SETTINGS_MODULE=config.settings.dev HBPRO_ENVIRONMENT=sandbox \
.venv/bin/python manage.py hbpro_ui_demo
```

Команда откажется запускаться на production settings, удалённой БД или БД с
другим именем. Настоящие credentials не используются и не меняются.

### Терминал 2: frontend

```bash
cd /Users/Apple/Desktop/projects/crm/CRM-Admin
npm install
BACKEND_URL=http://127.0.0.1:8000 npm run dev -- --hostname 127.0.0.1
```

**BACKEND_URL должен указывать на localhost.** Обычный `.env.local` проекта
может указывать на сервер. Переменная в команде выше переключает только этот
процесс, не изменяя `.env.local`.

Откройте **http://127.0.0.1:3000**. Если вход уже выполнен под другим аккаунтом,
выйдите и войдите в demo:

- Логин: `hotel-demo@local.test`
- Пароль: `Hotel-Demo-2026!`

### Проверка кнопок

1. Перейдите в «Заказы», найдите **HBPRO-DEMO-1**, откройте заказ.
2. Раскройте гостиничную услугу (кнопка глаза / «Показать детали»).
3. Нажмите **«Скачать сертификат на проживание (PDF)»**.
4. Откройте PDF: должна быть отметка демонстрации, отель, гость DEMO GUEST,
   даты и номер DEMO-NOT-REAL-1. Текст должен читаться по-русски.
5. Внутри заказа откройте вкладку **«Документы»**: сертификат должен быть там.
   Скачайте повторно: второго документа с тем же содержимым появляться не должно.
6. Вернитесь к услуге, нажмите **«Номера и фотографии гостиницы»**.
   Должны загрузиться «Стандарт (DEMO)» и «Семейный (DEMO)», тестовая картинка
   гостиницы и стандартного номера. Для семейного — сообщение об отсутствии фото.
7. Нажмите **«Скачать перечень номеров (CSV)»**. Откройте файл в Excel/Numbers:
   должны быть две категории и ссылки на картинки, кириллица без искажений.
8. Нажмите **«Открыть / сохранить фото»**: должна открыться локальная demo-картинка.
9. В заказе **HBPRO-DEMO-2** скачайте сертификат отменённой брони: в PDF должна
   быть заметная отметка отмены, а не действующее подтверждение проживания.
10. В заказе **HBPRO-DEMO-3** кнопка сертификата должна быть отключена, с текстом
    о необходимости подтверждения. Каталог номеров при этом доступен.

Остановка: `Ctrl+C` в обоих терминалах. Demo-БД остаётся для повторной проверки.
Обычная локальная БД и production при этом не меняются.

## Проверка реальных sandbox-данных после deployment

Для этой проверки нужен **уже существующий** sandbox-заказ с HBPRO-услугой.
Создавать и отменять новые бронирования ради проверки этих кнопок не нужно.

1. Обновить backend и frontend вместе; установить Python-зависимости из lockfile
   (добавлен reportlab и локальные шрифты Noto Sans). Перезапустить приложения.
   Новых миграций для этой доработки нет.
2. Открыть существующий заказ, раскрыть услугу, проверить PDF и вкладку «Документы».
3. Открыть каталог, проверить категории и фото именно из HBPRO. Если фото нет,
   проверить, возвращает ли поставщик `photos` / `images.variants` для этого отеля.
4. В «Подбор услуг → Гостиницы» выполнить только поиск и открыть «Выбрать номер» /
   «Подробнее о номерах»: каталог также доступен там. Это не бронирование.
5. Проверить IntegrationLog: при открытии каталога допустимы dictionary/hotel_details
   и при необходимости login. При формировании PDF обращений в HBPRO нет.
   createOrder/createBooking/cancel не должны появляться от этих действий.

Нужные права: `orders.view`, `documents.view`, `documents.generate` для сертификата;
`orders.view` для каталога услуги и `services.search` для каталога результата поиска.
Проверяется tenant и доступ к самому заказу.
